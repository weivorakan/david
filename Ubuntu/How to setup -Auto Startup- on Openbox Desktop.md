How to setup -Auto Startup- on Openbox Desktop

**Exported:** 5/6/2026 12:24:48  
**Link:** [https://gemini.google.com/app](https://gemini.google.com/app)

## Prompt:
เราสามารถมีวิธีไหนในการตั้งค่าเมื่อเริ่ม boot เครื่องเข้า tty1 ของ ubuntu server 26.04 LTS เพื่อให้เข้า openbox โดยอัตโนมัติได้บ้า่ง

## Response:
การตั้งค่าให้ Ubuntu Server 26.04 LTS (ซึ่งเป็นเวอร์ชันในอนาคตที่คุณอ้างถึง) บูตเข้าสู่ Openbox โดยตรงจาก tty1 โดยไม่ผ่าน Display Manager (เช่น GDM หรือ LightDM) สามารถทำได้หลายวิธีครับ แต่หัวใจสำคัญคือการจัดการกับ **Auto-login** และการสั่ง **Start GUI**

นี่คือวิธีที่นิยมและเสถียรที่สุดครับ:

* * *

### 1\. ตั้งค่า Auto-login สำหรับ tty1

ก่อนจะรัน Openbox ระบบต้องล็อกอินเข้า User ของคุณโดยอัตโนมัติก่อน โดยใช้ `systemd`

1.  สร้าง directory สำหรับ override config: `sudo mkdir -p /etc/systemd/system/getty@tty1.service.d`
2.  สร้างไฟล์คอนฟิก: `sudo nano /etc/systemd/system/getty@tty1.service.d/override.conf`
3.  ใส่เนื้อหาดังนี้ (เปลี่ยน `username` เป็นชื่อยูสเซอร์ของคุณ):
    ```
    [Service]
    ExecStart=
    ExecStart=-/sbin/agetty -o '-p -- \\u' --noclear --autologin username %I $TERM
    ```

* * *

### 2\. ตั้งค่าให้เรียก Openbox เมื่อ Login (ผ่าน .bash\_profile)

เมื่อ tty1 ทำการ login แล้ว เราจะสั่งให้มันเช็คว่าถ้าเป็น tty1 ให้เริ่มทำงาน X server ทันที

1.  แก้ไขไฟล์ `.bash_profile` (หรือสร้างขึ้นมาถ้าไม่มี): `nano ~/.bash_profile`
2.  เพิ่ม Code นี้ลงไปที่ท้ายไฟล์:
    ```
    if [ -z "$DISPLAY" ] && [ "$XDG_VTNR" -eq 1 ]; then
      exec startx
    fi
    ```
    _หมายเหตุ: `$XDG_VTNR -eq 1` คือการเช็คว่าเราอยู่ที่ tty1 เท่านั้น เพื่อไม่ให้มันพยายามเปิด GUI ซ้ำซ้อนถ้าคุณสลับไป tty อื่น_

* * *

### 3\. กำหนดค่าใน .xinitrc

ไฟล์นี้จะบอก `startx` ว่าต้องเปิดโปรแกรมอะไรบ้าง (ในที่นี้คือ Openbox)

1.  สร้างไฟล์ `.xinitrc` ใน Home directory: `nano ~/.xinitrc`
2.  ใส่คำสั่งเพื่อเรียก Openbox:
    ```
    # คุณสามารถใส่โปรแกรมที่จะให้รันตอนเริ่มได้ที่นี่ เช่น
    # nitrogen --restore & 
    # picom &
    exec openbox-session
    ```

* * *

### 4\. การติดตั้งเครื่องมือที่จำเป็น

เพื่อให้วิธีข้างต้นทำงานได้ คุณต้องมั่นใจว่าติดตั้ง package เหล่านี้ครบถ้วนแล้ว:

*   **Openbox**: ตัว Window Manager
*   **xinit**: เพื่อให้มีคำสั่ง `startx`
*   **xserver-xorg**: ระบบกราฟิกพื้นฐาน
    
```
sudo apt update
sudo apt install openbox xinit xserver-xorg
```

* * *

### สรุปขั้นตอนการทำงาน

*   **Step 1:** Systemd เรียกใช้ `getty` พร้อมพารามิเตอร์ `--autologin`
*   **Step 2:** Bash อ่าน `.bash_profile` และพบคำสั่ง `startx`
*   **Step 3:** `startx` อ่าน `.xinitrc` และทำการ `exec openbox-session`
*   **Result:** หน้าจอจะตัดจากบรรทัดคำสั่งเข้าสู่หน้าจอว่างๆ ของ Openbox ทันที

**ข้อควรระวัง:** วิธีนี้มีความเสี่ยงด้านความปลอดภัยเล็กน้อย เพราะใครก็ตามที่เปิดเครื่องจะเข้าถึงหน้าจอของคุณได้ทันทีโดยไม่ต้องใส่รหัสผ่าน หากเครื่องนี้ตั้งอยู่ในที่สาธารณะ ควรพิจารณาการใช้ Display Manager แบบปกติจะปลอดภัยกว่าครับ

## Prompt:
ผม save ไฟล์ override.conf ไม่ได้ครับ มันไม่ยอมให้ save

## Response:
ปัญหานี้เกิดจาก **สิทธิ์ (Permissions)** ครับ เนื่องจากโฟลเดอร์ `/etc/` เป็นพื้นที่ส่วนระบบของ Linux ยูสเซอร์ทั่วไปจะไม่สามารถเขียนหรือแก้ไขไฟล์ได้โดยตรง ต้องใช้สิทธิ์ **Root** (ผ่านคำสั่ง `sudo`) เท่านั้น

ลองทำตามขั้นตอนแก้ปัญหาดังนี้ครับ:

### 1\. ตรวจสอบการใช้ `sudo`

ตอนที่คุณเปิดไฟล์ด้วย `nano` คุณต้องพิมพ์ `sudo` นำหน้าเสมอเพื่อให้ระบบอนุญาตให้บันทึก:

```
sudo nano /etc/systemd/system/getty@tty1.service.d/override.conf
```

### 2\. ตรวจสอบว่า Folder มีอยู่จริงหรือไม่

บางครั้งถ้าเรายังไม่ได้สร้าง Folder ปลายทาง `nano` จะเปิดไฟล์ขึ้นมาได้ แต่จะบันทึกไม่ได้เพราะ "Path does not exist" ให้ลองรันคำสั่งสร้าง Folder อีกครั้งเพื่อความชัวร์:

```
sudo mkdir -p /etc/systemd/system/getty@tty1.service.d
```

### 3\. วิธีบันทึกและออกจาก Nano

เมื่อคุณใช้ `sudo nano` และแก้ไขเสร็จแล้ว ให้กดปุ่มดังนี้:

1.  กด **`Ctrl + O`** (เพื่อสั่ง Write Out/บันทึก)
2.  กด **`Enter`** (เพื่อยืนยันชื่อไฟล์)
3.  กด **`Ctrl + X`** (เพื่อออกจากโปรแกรม)

* * *

### ถ้ายังไม่ได้? (วิธีแก้แบบ "Force")

หากคุณติดปัญหาเรื่องการเปิดสิทธิ์ในตัว Editor ให้ลองใช้คำสั่ง `tee` ซึ่งจะรับข้อความจากบรรทัดคำสั่งแล้วเขียนลงไฟล์ด้วยสิทธิ์ sudo โดยตรง:

```
echo -e "[Service]\nExecStart=\nExecStart=-/sbin/agetty -o '-p -- \\\\u' --noclear --autologin YOUR_USERNAME %I \$TERM" | sudo tee /etc/systemd/system/getty@tty1.service.d/override.conf
```

_(อย่าลืมเปลี่ยน `YOUR_USERNAME` เป็นชื่อยูสเซอร์ของคุณก่อนรันนะครับ)_

**หลังจากเซฟไฟล์ได้แล้ว อย่าลืมสั่ง reload daemon เพื่อให้ระบบรับทราบการเปลี่ยนแปลงด้วยครับ:**

```
sudo systemctl daemon-reload
```

ติดขัดตรงบรรทัดไหน หรือมันขึ้น Error ข้อความว่าอะไรเป็นพิเศษไหมครับ?

## Prompt:
ใน ~/.xinitrc ผมมีการตั้งค่าทั้งเรื่องหน้าจอ และโดยเฉพาะ exec dbus-launch --exit-with-session openbox-session อยู่แล้ว ผมจะต้องใส่ exec openbox-session อีกครั้งต่อลงไปหรือไม่ หรือไม่ต้องเพิ่มอะไรแล้ว และมันต่างกันอย่างไร

## Response:
ไม่ต้องใส่เพิ่มครับ! หากคุณมีบรรทัด `exec dbus-launch ...` อยู่แล้ว **ห้าม** ใส่ `exec openbox-session` ต่อท้ายเด็ดขาด เพราะคำสั่งที่ขึ้นต้นด้วย `exec` จะเป็นคำสั่งสุดท้ายที่สคริปต์ทำงาน เมื่อมันรันเสร็จหรือปิดโปรแกรมนั้นลง มันจะจบการทำงานของ X session ทันที

### ความแตกต่างระหว่างสองคำสั่ง

| คำสั่ง | การทำงาน |
| --- | --- |
| **`exec openbox-session`** | รัน Openbox แบบเพียวๆ โดยไม่มีระบบบัสส่งข้อมูลระหว่างโปรแกรม (D-Bus) |
| **`exec dbus-launch --exit-with-session openbox-session`** | รัน Openbox พร้อมกับสร้าง instance ของ **D-Bus session bus** ขึ้นมาควบคู่กัน |

* * *

### ทำไมแบบ `dbus-launch` ถึงดีกว่า?

ใน Linux ยุคใหม่ โปรแกรมหลายตัว (เช่น File Manager, Network Manager, หรือแม้แต่การตั้งค่า Theme) จำเป็นต้องสื่อสารกันผ่าน D-Bus หากคุณใช้แค่ `exec openbox-session`:

*   โปรแกรมบางตัวอาจทำงานช้า (เพราะพยายามหา D-Bus แต่ไม่เจอ)
*   การ Mount USB drive อัตโนมัติอาจไม่ทำงาน
*   ฟังก์ชันอย่างการ Shutdown/Reboot ผ่านเมนู GUI อาจใช้ไม่ได้

การใช้ `dbus-launch --exit-with-session` จึงเป็นการบอกระบบว่า: _"ช่วยเปิด D-Bus ให้ Openbox ใช้ด้วย และถ้าฉันปิด Openbox เมื่อไหร่ ก็ให้ปิด D-Bus ตามไปเลยนะ"_

* * *

### ข้อควรระวังในการเรียงลำดับไฟล์ `.xinitrc`

เพื่อให้การตั้งค่าหน้าจอและโปรแกรมอื่นๆ ทำงานถูกต้อง ลำดับในไฟล์ควรเป็นดังนี้ครับ:

```
# 1. ตั้งค่าหน้าจอ (ต้องใส่ & ไว้ข้างหลังเพื่อให้ทำงานเป็น background)
xrandr --output HDMI-1 --mode 1920x1080 &

# 2. รันโปรแกรมเสริมอื่นๆ (ต้องใส่ & เสมอ)
nitrogen --restore &
picom &

# 3. คำสั่งสุดท้าย (ห้ามใส่ & และต้องมี exec)
exec dbus-launch --exit-with-session openbox-session
```

> **กฎเหล็ก:** ในไฟล์ `.xinitrc` จะมีคำสั่งที่ขึ้นต้นด้วย `exec` ได้เพียง **บรรทัดเดียว** และต้องอยู่บรรทัดสุดท้ายเสมอครับ

ตอนนี้ใน `.xinitrc` ของคุณมีการใส่เครื่องหมาย `&` ไว้หลังคำสั่งตั้งค่าหน้าจอแล้วหรือยังครับ? เพราะถ้าลืมใส่ ระบบจะหยุดรอที่คำสั่งตั้งหน้าจอจนกว่าคุณจะปิดมัน ถึงจะยอมไปรัน Openbox ต่อได้ครับ

## Prompt:
มีใส่ '&' ไว้ในบรรทัดถัดไปหลังจาก xrandr คือ xsetroot -cursor\_name left\_ptr & ใช้ได้เหมือนกันหรือไม่

## Response:
ใช้ได้ครับ และถือเป็นวิธีที่ถูกต้องแล้วครับ

หลักการคือโปรแกรมอะไรก็ตามที่เป็น **"เครื่องมือเสริม"** (Utility) หรือการตั้งค่าสภาพแวดล้อม (Environment) จะต้องใส่ `&` ไว้ข้างหลังเสมอ เพื่อให้กระบวนการ (Process) นั้นทำงานในเบื้องหลัง และปล่อยให้สคริปต์รันบรรทัดถัดไปได้ทันที

### ตรวจสอบความถูกต้องของลำดับ

ลำดับที่คุณใช้ควรจะเป็นลักษณะนี้:

```
# 1. การตั้งค่าหน้าจอ
xrandr --output Virtual1 --mode 1920x1080 &

# 2. การตั้งค่าเคอร์เซอร์ (ที่คุณถามถึง)
xsetroot -cursor_name left_ptr &

# 3. (ถ้ามี) โปรแกรมอื่นๆ เช่น wallpaper, panel
# nitrogen --restore &

# 4. บรรทัดสุดท้ายที่เป็นตัวเข้าหน้าจอหลัก
exec dbus-launch --exit-with-session openbox-session
```

* * *

### ทำไมต้องใส่ `&` ที่ `xsetroot`?

*   **ถ้าใส่ `&`:** ระบบจะสั่งเปลี่ยนรูปตัวชี้เมาส์ (cursor) ให้เป็นลูกศร แล้วข้ามไปรันบรรทัดถัดไปทันที ทำให้เข้า Openbox ได้เร็ว
*   **ถ้าไม่ใส่ `&`:** ในบางกรณีหากคำสั่ง `xsetroot` ทำงานช้าหรือเกิดอาการค้าง สคริปต์ `.xinitrc` จะหยุดรออยู่ตรงนั้นและไม่ยอมไปรัน `exec openbox-session` ทำให้คุณค้างอยู่ที่หน้าจอดำๆ นานกว่าปกติ

### ข้อสังเกตเพิ่มเติม

สำหรับ `xrandr` และ `xsetroot` นั้นเป็นคำสั่งที่ทำงานแป๊บเดียวเสร็จ (Run and exit) การใส่ `&` หรือไม่ใส่ อาจจะไม่เห็นความแตกต่างชัดเจนเท่ากับโปรแกรมที่ต้องรันค้างไว้ตลอดเวลาอย่าง `picom` (ตัวทำโปร่งใส) หรือ `polybar` (แถบเมนู)

แต่การใส่ `&` ไว้ที่ `xsetroot -cursor_name left_ptr &` **เป็นแนวทางปฏิบัติที่ดี (Best Practice)** เพื่อป้องกันไม่ให้ลำดับการบูตถูกขัดจังหวะครับ

ตอนนี้ลอง Reboot เครื่องดูหรือยังครับว่ามันเข้าหน้า Openbox พร้อมเมาส์ลูกศรตามที่ต้องการไหม?

## Prompt:
startx จะอ่าน .xinitrc ก่อนหรือหลัง ~/.config/autostart พอดีผมมีคำสั่งใน ~/.bashrc ที่ผมอยากใช้หลังจาก startx รันมาได้ซักพักนึงแล้ว

## Response:
ลำดับการทำงานของ Linux GUI ในระดับนี้มีความเฉพาะตัวครับ เพื่อให้คุณวางแผนการใช้คำสั่งใน `~/.bashrc` ได้ถูกจังหวะ มาดูลำดับเหตุการณ์ (Execution Flow) กันครับ:

### 1\. ลำดับการอ่านไฟล์ (Execution Order)

1.  **`~/.bash_profile`**: เมื่อคุณ Login ที่ tty1 ไฟล์นี้จะถูกอ่านก่อนเพื่อน และเป็นตัวสั่ง `startx`
2.  **`~/.xinitrc`**: เมื่อ `startx` ทำงาน มันจะมาอ่านไฟล์นี้เป็นอันดับแรก เพื่อดูว่าจะให้เปิด Window Manager ตัวไหน (เช่น Openbox)
3.  **`~/.config/openbox/autostart`**: เมื่อ Openbox เริ่มทำงาน (ผ่านคำสั่ง `exec openbox-session` ใน .xinitrc) มันถึงจะเริ่มไปอ่านสคริปต์ autostart ของตัวมันเอง
4.  **`~/.config/autostart/*.desktop`**: ไฟล์เหล่านี้จะถูกอ่านโดยโปรแกรมจำพวก Session Manager หรือถ้าคุณใช้ Openbox คุณต้องติดตั้งเครื่องมืออย่าง `dex` เพื่อสั่งรันไฟล์ .desktop เหล่านี้อีกที

**สรุปคือ:** `~/.xinitrc` ทำงาน **ก่อน** โฟลเดอร์ autostart เสมอครับ

* * *

### 2\. แล้ว ~/.bashrc จะทำงานตอนไหน?

ไฟล์ `~/.bashrc` จะถูกอ่าน **ทุกครั้งที่คุณเปิด Terminal (Interactive Shell)** ครับ

*   มัน **ไม่ได้** รันตอนบูตเครื่องโดยตรง
*   มัน **ไม่ได้** รันพร้อม Openbox
*   มันจะรันก็ต่อเมื่อคุณเปิด `xterm`, `terminator` หรือ Terminal อื่นๆ ขึ้นมาใน Openbox เท่านั้น

> **คำเตือน:** การใส่คำสั่งที่ให้รัน "หลังจาก startx รันมาได้ซักพัก" ไว้ใน `~/.bashrc` อาจจะไม่ใช่ไอเดียที่ดีนัก เพราะทุกครั้งที่คุณเปิดหน้าต่าง Terminal ใหม่ คำสั่งนั้นจะทำงานซ้ำแล้วซ้ำอีกครับ

* * *

### 3\. วิธีแนะนำ: การใช้คำสั่งหลังจากเข้า GUI แล้ว (Delayed Execution)

หากคุณต้องการรันคำสั่งบางอย่างหลังจากเข้า Openbox มาได้สักพัก (เช่น รอให้ระบบ Network หรือระบบภาพเสถียรก่อน) แนะนำให้ใส่ไว้ใน **`~/.config/openbox/autostart`** โดยใช้คำสั่ง `sleep` ครับ

**ตัวอย่างในไฟล์ `~/.config/openbox/autostart`:**

```

(sleep 10 && /path/to/your/script.sh) &
```

### วิธีที่ 1: ใช้ `dex` (ตามที่คุณเพิ่งติดตั้งไป)

ในเมื่อคุณใช้ `dex` อยู่แล้ว วิธีที่สะอาดที่สุดคือการสร้างไฟล์ `.desktop` ส่วนตัวขึ้นมา ซึ่งวิธีนี้จะช่วยให้ระบบจัดการการรันโปรแกรมได้มาตรฐานกว่า

1.  สร้างไฟล์ใหม่ในโฟลเดอร์ autostart: `nano ~/.config/autostart/delayed-xterm.desktop`
2.  ใส่เนื้อหาดังนี้:
    ```
    [Desktop Entry]
    Type=Application
    Name=Delayed Xterm
    # สั่งให้รอ 10 วินาที แล้วเปิด xterm พร้อมรันคำสั่ง
    Exec=bash -c "sleep 10 && xterm -hold -e 'echo Hello World; bash'"
    Terminal=false
    ```
    *   `-hold`: สั่งให้ xterm ค้างหน้าจอไว้ ไม่ปิดตัวลงหลังจากคำสั่งแรกทำงานเสร็จ
    *   `-e '...; bash'`: สั่งให้รันคำสั่งที่ต้องการ แล้วตบท้ายด้วย `bash` เพื่อให้คุณสามารถพิมพ์คำสั่งต่อบน prompt ได้

### วิธีที่ 2: ใช้ `.xinitrc` (ก่อนเข้า Openbox)

หากคุณไม่อยากยุ่งกับไฟล์ในกลุ่ม autostart เลย คุณสามารถดักไว้ที่ `.xinitrc` ตั้งแต่ก่อนเข้า Openbox ได้ โดยใช้เทคนิค **Background Subshell** ครับ

1.  แก้ไขไฟล์ `~/.xinitrc`: `nano ~/.xinitrc`
2.  เพิ่มบรรทัดนี้ลงไป **"ก่อน"** บรรทัด `exec dbus-launch ...`:
    ```
    # สร้าง Subshell ให้ทำงานขนานไปเบื้องหลัง
    (sleep 10 && DISPLAY=:0 xterm -hold -e "echo 'Welcome back!'; bash") &
    ```
    *   การใส่ `&` และวงเล็บ `()` สำคัญมาก เพราะมันจะสั่งให้ระบบ "นับเวลาถอยหลัง 10 วินาทีในใจ" ในขณะที่ตัวมันเองก็รัน Openbox ขึ้นมาทันทีโดยไม่ต้องรอให้ครบ 10 วินาทีก่อน

### ทำไมวิธีที่คุณเคยทำอาจจะไม่ได้ผล?

*   **ไม่มี `&` ท้ายบรรทัด:** หากในสคริปต์ไม่มี `&` Openbox จะหยุดทำงานทุกอย่างเพื่อรอให้คำสั่งนั้นเสร็จก่อน ซึ่ง xterm จะไม่โผล่จนกว่า Openbox จะโหลดเสร็จ (วนลูปกันเอง)
*   **Environment ของคำสั่ง:** การจะเปิด xterm แล้วให้ "พิมพ์ต่อได้" ต้องสั่งให้มันเรียก `bash` ซ้ำซ้อนเข้าไปข้างใน ไม่เช่นนั้นพอ xterm รันคำสั่งที่คุณตั้งไว้เสร็จ มันจะปิดหน้าต่างตัวเองทิ้งทันที
*   **Variable `DISPLAY`:** บางครั้งสคริปต์รันเร็วเกินไปจนยังหาหน้าจอ (Display) ไม่เจอ การใส่ `sleep` หรือระบุ `DISPLAY=:0` จะช่วยแก้ปัญหานี้ได้ครับ

**คำแนะนำเพิ่มเติม:** ถ้าคำสั่งที่คุณต้องการพิมพ์บน prompt เป็นคำสั่งที่ต้องใช้บ่อยๆ การสร้าง **Alias** ไว้ใน `~/.bashrc` จะช่วยให้คุณพิมพ์สั้นลงมากเมื่อ xterm เด้งขึ้นมาแล้วครับ

### วิธีแก้ไขและตรวจสอบเบื้องต้น (Step-by-Step)

1.  **ตรวจสอบการรัน Startx:** ลองกด `Ctrl + Alt + F2` เพื่อสลับไป tty2 แล้ว Login เข้าไป จากนั้นพิมพ์ `pgrep Xorg` หรือ `pgrep openbox` ถ้าไม่ขึ้นเลข Process แสดงว่า `startx` ยังไม่ถูกรันจาก tty1
2.  **แก้ไข `.bash_profile`:** ตรวจสอบให้แน่ใจว่าไฟล์ `~/.bash_profile` มีเนื้อหาดังนี้:
    ```
    if [ -f ~/.bashrc ]; then
        . ~/.bashrc
    fi
    if [ -z "$DISPLAY" ] && [ "$XDG_VTNR" -eq 1 ]; then
        exec startx
    fi
    ```
