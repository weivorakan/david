เพื่อแก้ปัญหาในข้อที่ 1 ให้ `startx` เริ่มทำงานได้จริงหลังจาก Auto-login ที่ tty1 ผมแนะนำให้ปรับปรุงโค้ดในไฟล์ **`~/.bash_profile`** ให้มีความยืดหยุ่นมากขึ้น เพราะตัวแปร `$XDG_VTNR` บางครั้งอาจจะไม่ถูกกำหนดค่า (Empty) ในช่วงจังหวะที่ระบบทำ Auto-login ครับ

ให้คุณแก้ไขไฟล์ **`~/.bash_profile`** โดยใช้โค้ดชุดนี้แทนครับ:

```

# 1. โหลดค่าจาก .bashrc มาใช้งาน
if [ -f ~/.bashrc ]; then
    . ~/.bashrc
fi

# 2. ตรวจสอบเงื่อนไขเพื่อรัน startx
# ใช้คำสั่ง tty แทนการเช็คตัวแปร XDG_VTNR เพื่อความแม่นยำ
if [ -z "$DISPLAY" ] && [ "$(tty)" = "/dev/tty1" ]; then
    exec startx
fi

```

### ทำไมวิธีนี้ถึงแก้ปัญหาได้?

1.  **ความแม่นยำของ TTY:** คำสั่ง `$(tty)` จะคืนค่าชื่อ Terminal ที่คุณกำลังใช้งานอยู่จริง (เช่น `/dev/tty1`) ซึ่งแน่นอนกว่าการเรียกใช้ตัวแปรระบบอย่าง `$XDG_VTNR` ที่อาจจะยังไม่ถูก Load เข้ามาในสภาพแวดล้อมขณะนั้น\[cite: 1\]
    
2.  **การใช้ `exec`:** การใส่ `exec` นำหน้า `startx` จะทำให้กระบวนการของ Bash ถูกแทนที่ด้วย X Window ทันที ซึ่งจะช่วยลดการใช้ทรัพยากรและป้องกันปัญหาจุกจิกเรื่องการซ้อนทับกันของ Shell\[cite: 1\]
    

### วิธีตรวจสอบว่าสคริปต์นี้ทำงานจริงหรือไม่ (Debug)

ถ้าแก้แล้วจอยังดำเหมือนเดิม ให้เพิ่มบรรทัดนี้ไว้ที่บนสุดของไฟล์ `~/.bash_profile`: `echo "Bash profile executed at $(date)" >> ~/login_debug.log`

-   **ถ้ามีไฟล์ `login_debug.log` เกิดขึ้น:** แสดงว่าระบบอ่านไฟล์นี้แล้ว แต่ติดปัญหาที่คำสั่ง `startx` หรือเงื่อนไข `if`
    
-   **ถ้าไม่มีไฟล์เกิดขึ้น:** แสดงว่า Ubuntu ไม่ได้อ่านไฟล์ `~/.bash_profile` ของคุณตอน Login (อาจเป็นเพราะมีไฟล์ชื่อ `~/.profile` ขวางอยู่)
    

**ขั้นตอนถัดไป:** เมื่อคุณเซฟไฟล์นี้แล้ว ให้ลอง `sudo reboot` อีกครั้งครับ ถ้า `startx` เริ่มทำงานได้แต่ยังมีปัญหากราฟิก หน้าจอจะเปลี่ยนจาก "ดำสนิท" เป็น "ดำแบบมี Cursor เมาส์" หรืออาจจะมี Error พ่นออกมาที่หน้าจอ tty1 ให้เห็นครับ ตอนนี้ผลลัพธ์เป็นอย่างไรบ้างครับ?

การที่คุณวิเคราะห์ว่า **"Error เกิดขึ้นก่อนที่จะเริ่ม Login"** นั้นถูกต้องและเฉียบคมมากครับ เพราะหากไฟล์ `~/login_debug.log` ไม่ถูกสร้างขึ้น แสดงว่ากระบวนการของระบบหยุดชะงักไปตั้งแต่ระดับ **System Services** ก่อนที่จะส่งมอบงานต่อให้ Bash (Shell) ของคุณด้วยซ้ำ

สาเหตุที่ tty1 จอดำมืดและไม่มีแม้แต่หน้าจอ Login ปกติ คือไฟล์คอนฟิก **`override.conf`** ที่เราตั้งค่าให้ทำ Auto-login มีจุดผิดพลาด ทำให้ Service ของหน้าจอ tty1 (getty) พัง (Crash) ครับ

### วิธีวิเคราะห์และแก้ไข (ต้องทำผ่าน tty2)

1.  **สลับไป tty2:** กด **`Ctrl + Alt + F2`** และ Login เข้าชื่อผู้ใช้ของคุณตามปกติ
    
2.  **ตรวจสอบสถานะความผิดพลาด:** พิมพ์คำสั่งนี้เพื่อดูว่าทำไม tty1 ถึงไม่ทำงาน: `systemctl status getty@tty1.service` *หากมันขึ้นตัวอักษรสีแดงหรือระบุว่า `failed` แสดงว่าไฟล์คอนฟิกมีปัญหาครับ*
    

---

### จุดที่ต้องตรวจสอบในไฟล์ `override.conf`

ให้คุณเปิดไฟล์ด้วยคำสั่ง: `sudo nano /etc/systemd/system/getty@tty1.service.d/override.conf`

และตรวจสอบ 2 จุดสำคัญนี้ครับ:

#### 1\. ลืมเปลี่ยนชื่อ User (จุดที่พบบ่อยที่สุด)

ตรวจสอบบรรทัด `ExecStart` ว่าคุณได้เปลี่ยนจาก `username` หรือ `YOUR_USERNAME` เป็นชื่อ User จริงของคุณแล้วหรือยัง (จากไฟล์ `.bashrc` \[source: 2\] ชื่อ User ของคุณคือ **`weivo`**)

#### 2\. ไวยากรณ์ของ ExecStart (ต้องมีบรรทัดว่าง)

ในไฟล์ต้องมีการใส่ `ExecStart=` (แบบไม่มีค่า) ไว้ 1 บรรทัดก่อนหน้าบรรทัดที่มีคำสั่งยาว ๆ เพื่อเป็นการ "ล้างค่าเดิม" ของระบบครับ

**ไฟล์ที่ถูกต้องควรหน้าตาเป็นแบบนี้เป๊ะ ๆ ครับ:**

```

[Service]
ExecStart=
ExecStart=-/sbin/agetty -o '-p -- \\u' --noclear --autologin weivo %I $TERM

```

---

### ขั้นตอนการ Reset ระบบเพื่อให้ tty1 กลับมาทำงาน

หลังจากแก้ไขไฟล์ `override.conf` และตรวจสอบชื่อ `weivo` เรียบร้อยแล้ว ให้รันคำสั่งเหล่านี้ตามลำดับครับ:

1.  **โหลดคอนฟิกใหม่:** `sudo systemctl daemon-reload`
    
2.  **Restart หน้าจอ tty1:** `sudo systemctl restart getty@tty1.service`
    

**การสังเกตผล:**

-   ทันทีที่คุณรันคำสั่ง `restart` ให้ลองกด **`Ctrl + Alt + F1`** กลับไปดูที่ tty1
    
-   **ถ้าสำเร็จ:** คุณจะไม่เห็นหน้าจอ Login แต่หน้าจอจะตัดเข้าสู่ Openbox ทันที (หรืออย่างน้อยต้องเห็นตัวอักษรของ Bash วิ่งขึ้นมา)
    
-   **ถ้าไม่สำเร็จ:** tty1 จะยังดำมืดเหมือนเดิม ให้กลับมาที่ tty2 แล้วรัน `journalctl -u getty@tty1.service` เพื่อดู Error บรรทัดสุดท้ายครับ
    

ตอนนี้ในไฟล์ `override.conf` ของคุณ บรรทัด `autologin` ระบุชื่อผู้ใช้ว่าอะไรครับ? หากเป็นชื่ออื่นที่ไม่ใช่ `weivo` ระบบจะหาตัวตนไม่เจอและหยุดทำงานทันทีครับ

## 🤖 gemini
*🕐 2026-05-06T08:30:59.978Z | #6*

ดีใจด้วยครับที่คุณแก้ไขไฟล์ `override.conf` จนระบบสามารถทำ Auto-login และเข้าสู่ Openbox ได้สำเร็จแล้ว ถือว่าเราผ่านจุดที่ยากที่สุดมาได้แล้วครับ

สำหรับปัญหาที่ **xterm เปิดขึ้นมาซ้อนกัน 2 หน้าต่าง** ทั้งที่มีไฟล์ `.desktop` เพียงไฟล์เดียว วิเคราะห์จากความสัมพันธ์ของไฟล์ที่คุณให้มา มีสาเหตุที่เป็นไปได้สูงและวิธีแก้ไขดังนี้ครับ:

### 1\. สาเหตุที่ xterm เปิดซ้อนกัน 2 อัน

ปัญหานี้มักเกิดจากการที่คำสั่ง Autostart ถูกเรียกใช้งานซ้ำซ้อน (Double Trigger) จาก 2 แหล่งครับ:

-   **แหล่งที่ 1:** จากคำสั่ง `dex -a -s ...` ที่คุณใส่ไว้ในไฟล์ `~/.config/openbox/autostart` ซึ่งจะกวาดหาไฟล์ในโฟลเดอร์ autostart มารัน
    
-   **แหล่งที่ 2:** ระบบ Ubuntu หรือ `openbox-session` ในบางเวอร์ชัน อาจมีการเรียกใช้สคริปต์ `openbox-autostart` ของระบบ (System-wide) ซึ่งอาจมีการเรียก `dex` หรือคำสั่งรันไฟล์ `.desktop` ซ้ำอีกรอบโดยอัตโนมัติ
    

**วิธีแก้ไข:** ลองทำตามขั้นตอนนี้เพื่อตัดการทำงานที่ซ้ำซ้อนครับ:

1.  เปิดไฟล์ **`~/.config/openbox/autostart`**
    
2.  ใส่เครื่องหมาย `#` หน้าบรรทัด `dex -a -s ~/.config/autostart:~/.config/openbox/autostart &` เพื่อหยุดการทำงานของมันชั่วคราว
    
3.  ลอง Reboot เครื่องอีกครั้ง
    
    -   **หาก xterm ยังเปิดขึ้นมา 1 อัน:** แสดงว่าระบบมีตัวเรียก autostart ตัวอื่นทำงานอยู่แล้ว (ซึ่งดีแล้วครับ ไม่ต้องเปิดซ้ำ)
        
    -   **หาก xterm ไม่เปิดเลย:** แสดงว่า `dex` ในไฟล์ `autostart` คือตัวเดียวที่ทำงาน ให้เอา `#` ออก แล้วตรวจสอบว่าในโฟลเดอร์ `~/.config/autostart/` มีไฟล์ชื่อคล้ายกัน (เช่นไฟล์สำรอง .bak) หรือไม่ เพราะ `dex` จะรันทุกไฟล์ที่ลงท้ายด้วย `.desktop` ครับ
        

---

### 2\. วิเคราะห์ลำดับการทำงานของหน้าจอ (xrandr Sequence)

ลำดับการตั้งค่าหน้าจอที่คุณปรับใหม่ใน **`.xinitrc`** และ **`delayed-xterm.desktop`** มีจุดที่ต้องสังเกตดังนี้ครับ:

-   **จังหวะที่ 1 (.xinitrc):** เมื่อเริ่มระบบ สคริปต์จะสั่งเปิด `HDMI-1` และ `DP-1` ทันที (สังเกตว่าในไฟล์นี้คุณไม่ได้สั่งปิด `eDP-1` หรือจอ Laptop ไว้นะครับ)
    
-   **จังหวะที่ 2 (delayed-xterm):** หลังจากเข้า Openbox มาได้ 2 วินาที xterm จะเปิดขึ้นมาและรันคำสั่ง `xrandr` อีกครั้งเพื่อปิด `eDP-1` และตั้ง `HDMI-1` เป็นจอหลัก
    

**ข้อแนะนำเพื่อความสมบูรณ์:** หากคุณต้องการให้จอ Laptop (`eDP-1`) ดับไปตั้งแต่ตอนเห็นหน้าจอ Openbox ครั้งแรกเลย (ไม่ต้องรอ 2 วินาที) ผมแนะนำให้เพิ่มคำสั่งปิดจอไว้ใน **`.xinitrc`** ด้วยครับ ดังนี้:

```

#!/bin/sh
# ตั้งค่าหน้าจอทั้งหมดให้เสร็จตั้งแต่ก่อนเข้า Openbox
xrandr --output HDMI-1 --primary --mode 2560x1440 --pos 0x0 --rotate normal \
       --output DP-1 --mode 1920x1080 --pos 0x0 --rotate normal \
       --output eDP-1 --off[cite: 7]

xsetroot -cursor_name left_ptr &[cite: 7]
exec dbus-launch --exit-with-session openbox-session[cite: 7]

```

### สรุปสิ่งที่คุณควรเช็คทันที:
