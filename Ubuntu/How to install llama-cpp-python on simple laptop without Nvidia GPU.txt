How to install llama-cpp-python on simple laptop without Nvidia GPU

### 1\. ดาวน์โหลดและ Build Python 3.11.9
เราจะโหลดโค้ดต้นฉบับจากเว็บหลักของ Python มา "ต้ม" เองในเครื่องครับ:
```
# 1. ไปที่โฟลเดอร์เก็บไฟล์ชั่วคราว
cd /tmp

# 2. ดาวน์โหลด Source Code 3.11.9
wget https://www.python.org/ftp/python/3.11.9/Python-3.11.9.tgz

# 3. แตกไฟล์
tar -xf Python-3.11.9.tgz
cd Python-3.11.9

# 4. Configure ระบบ (เน้นความเร็วและเสถียรภาพ)
./configure --enable-optimizations --with-ensurepip=install

# 5. สั่ง Build (ใช้ 8 Cores ของ Ryzen 7 ให้คุ้ม)
make -j8 2>&1 | tee make_error.log
*   **2\>&1**: สั่งให้เก็บ Error (Standard Error) มารวมกับข้อความปกติ
*   **tee**: ทำหน้าที่แสดงผลบนหน้าจอด้วย และเขียนลงไฟล์ `make_error.log` ไปพร้อมๆ กัน
*   nano make_error.log แล้ว Search หาคำว่า **"error:"** (พิมพ์ตัวเล็กทั้งหมด) คุณจะเจอจุดที่มันพังทันทีครับ
ถ้าคุณเห็น Error พุ่งมาเยอะๆ ส่วนใหญ่มักจะเกิดจาก **"วัตถุดิบ"** ไม่ครบครับ ให้ลองเช็ค 3 ตัวนี้เป็นพิเศษ:
*   **`zlib`**: ถ้าตัวนี้พัง จะขึ้น Error เกี่ยวกับ `compression`
*   **`libssl`**: ถ้าตัวนี้พัง จะมีปัญหาเรื่อง `_ssl` module (ซึ่งจะทำให้ใช้ `pip` ไม่ได้)
*   **`libffi`**: ถ้าตัวนี้พัง จะคอมไพล์ส่วนที่ติดต่อกับระบบภายนอก (อย่าง Vulkan) ไม่สำเร็จ

# 6. ติดตั้งแบบ altinstall (เพื่อไม่ให้ไปทับ Python 3.14 ของระบบ)
sudo make altinstall
```

* * *

เมื่อเสร็จแล้ว ให้ลองเช็คว่า Python ตัวใหม่มาหรือยัง: `python3.11 --version` ถ้าขึ้นว่า **Python 3.11.9** แสดงว่าเรา "ล้างอาถรรพ์" ของ 3.14 สำเร็จแล้วครับ

* * *

### 2\. เริ่มลุย David ใน Environment ใหม่

กลับไปที่โฟลเดอร์ David ของคุณ แล้วสร้าง Virtual Environment ใหม่ด้วย Python 3.11.9 ตัวที่เราเพิ่งสร้างขึ้นมาครับ:

```
# 1. เข้าไปที่โฟลเดอร์โปรเจกต์
cd ~/david

# 2. ลบ venv เก่าทิ้งอีกครั้งเพื่อความชัวร์
rm -rf venv

# 3. สร้าง venv ใหม่ด้วย Python 3.11
python3.11 -m venv venv

# 4. Activate
source venv/bin/activate
```

#### 3\. เตรียมพื้นที่และดึงซอร์สโค้ด (Git Clone)
เราจะทำงานในโฟลเดอร์ที่สะอาดที่สุดภายใน Virtual Environment ของคุณ
```
source ~/david/venv/bin/activate
cd ~/david
# ลบโฟลเดอร์เดิมทิ้งก่อน (ถ้ามี) เพื่อล้างอาถรรพ์
rm -rf llama-cpp-python
git clone --recursive https://github.com/abetlen/llama-cpp-python.git
cd llama-cpp-python
```

#### 4\. บังคับให้ CMake เห็น Vulkan แบบตรงๆ
สาเหตุที่ CMake พัง มักเป็นเพราะมันหาตำแหน่งของ Vulkan ใน Ubuntu 26.04 ไม่เจอ เราจะใช้คำสั่งนี้เพื่อสร้างไฟล์คอมไพล์โดยตรง

##### ลงเครื่องมือ glslc ซึ่งเป็น Shader Compiler (ผ่าน Repository มาตรฐาน)
เหตุผลที่เราต้องหา `glslc` ให้เจอ เพราะมันคือตัวเดียวที่จะ **"ปลดล็อก"** ให้ iGPU ของ Ryzen 7 ทำงานได้ครับ
*   ถ้าเราข้ามจุดนี้ไป ระบบจะถอยกลับไปใช้ CPU ล้วนเหมือนเดิม
*   และการรัน **Gemma 4** บน GPU จะเร็วกว่า CPU อย่างเห็นได้ชัด รวมถึงช่วยลดความร้อนของ CPU 8 Cores ของคุณในระยะยาวด้วยครับ
```
sudo apt install -y glslc glslang-tools libshaderc-dev
```
*   **`glslang-tools`**: จะติดตั้ง `glslangValidator` ซึ่งทำงานแทนกันได้ในบางกรณี
*   **`libshaderc-dev`**: ตัวนี้มักจะแถมไฟล์ **`glslc`** มาให้ด้วยใน `/usr/bin/` ครับ
หลังจากรันคำสั่งด้านบนเสร็จแล้ว ให้ลองเช็คด้วยคำสั่งนี้ครับ:
```
which glslc
```
ถ้าขึ้น Path เช่น `/usr/bin/glslc` แสดงว่า **"กุญแจดอกสุดท้าย"** อยู่ในมือคุณแล้วครับ
**หมายเหตุ:** หากติดตั้งทั้งสองอย่างแล้วยังหาไม่เจอ ให้ลองสั่ง `sudo apt install -y google-shaderc` (ถ้ามีใน Repo ของรุ่น 26.04)

##### หลังจากนี้ให้เริ่ม Building Wheel
mkdir build
cd ~/david/llama-cpp-python/build
cmake .. -DGGML_VULKAN=on
# ถ้ารันบรรทัดบนแล้วผ่าน (ไม่มีคำว่า Error) ให้รันต่อเลยครับ
cmake --build . --config Release -j8
```
_หากบรรทัด `cmake ..` พัง มันจะบอกชื่อไฟล์ที่หายไปทันที (เช่น vulkan.h) ซึ่งเราจะแก้ได้ถูกจุดครับ_

* * *

#### 5\. ติดตั้งเข้า Python 3.11.9
เมื่อคอมไพล์ตัวหลักเสร็จแล้ว เราค่อยสั่งติดตั้งส่วนเชื่อมต่อ (Python Wrapper) เข้าไปครับ
```
cd ..
pip install .
```

* * *

**หมายเหตุ:** เมื่อใช้ venv แล้ว ต้องติดตั้ง Library ที่ต้องใช้ทั้งหมดใน venv ใหม่ทั้งหมด
python -m pip install langchain-community langchain-core langchain-text-splitters faiss-cpu pypdf pydantic pandas requests transformers pillow sentence_transformers torch fastapi uvicorn einops

* * *

#### 6\. เมื่อลงทั้งหมดสำเร็จแล้ว ให้ตรวจสอบการ Activate Virtual Environment (สำคัญที่สุด)
ทุกครั้งที่คุณเปิด TTY ใหม่ หรือสลับหน้าจอ คุณต้องสั่ง "เปิดใช้งาน" สภาพแวดล้อมก่อนเสมอ เพื่อให้ระบบรู้ว่าต้องไปดึง `llama_cpp และ Python และ Library` จากใน `venv` มาใช้
```
source ~/david/venv/bin/activate
```
_สังเกตว่าหน้าชื่อ User ของคุณต้องมีคำว่า **`(venv)`** ปรากฏอยู่ครับ_

#### เช็คว่า `llama-cpp-python` อยู่ในรายชื่อหรือไม่
เมื่อ Activate แล้ว ให้ลองใช้คำสั่งนี้เช็คดูครับ:
```
pip list | grep llama
```
_หากไม่พบชื่อในรายการ แสดงว่าตอนที่คุณสั่ง `pip install .` ในโฟลเดอร์ที่ Build คุณอาจจะยังไม่ได้ Activate venv ทำให้มันหลุดไปลงที่ Python หลักของระบบครับ_

* * *

### 7\. การใส่ `venv` auto activation ไว้ใน `.bashrc`
หากคุณต้องการให้ทุกครั้งที่สลับไป TTY ไหนก็ตาม ระบบ Activate ให้คุณทันที:
1.  พิมพ์ `nano ~/.bashrc`
2.  ไปที่บรรทัดล่างสุดแล้วเพิ่ม: `source ~/david/venv/bin/activate`
3.  บันทึกด้วย Ctrl-O จากนั้นกด Enter และออกด้วย Ctrl-X
4.  จากนั้นพิมพ์ `source ~/.bashrc`
เมื่อมี `(venv)` ขึ้นแล้ว คุณสามารถใช้คำสั่งรันได้เลยตามที่คุณเข้าใจครับ:
```
cd ~/david
python david_server_CPU.py
```
_หมายเหตุ: ใน venv คุณสามารถใช้คำสั่ง `python` สั้นๆ ได้เลย (ไม่ต้องเติมเลข 3) เพราะระบบจะชี้ไปที่ Python 3.11.9 ตัวที่เราเพิ่งประกอบร่างกันมาโดยอัตโนมัติครับ_
